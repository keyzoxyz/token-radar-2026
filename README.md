An entry for the make.fun bounty **“Build the best token launch radar”** — [make.fun/bounty/token-radar-01](https://make.fun/bounty/token-radar-01).

Every protocol in the snapshot that records no token — no market cap, no CoinGecko id, no symbol — is ranked by an
implied value, and each row carries the farm plan that follows from its own record. The dashboard is three static files
and one `data.js`; there is no network call at runtime, before or after load.

## The model

One function scores every row, and no protocol name is ever special-cased:

```
implied_value = tvl_usd
              × base_multiple        measured from the snapshot, not chosen
              × growth_multiplier    change_7d, clamped and weighted
              × relative_multiplier  change_7d against the category's median
              × patience_multiplier  how long the record has run with no token
              × category_multiplier  the category's median TVL against the universe's, on a log scale
              × breadth_multiplier   how many chains the record spans
```

**The base multiple is measured, not picked.** Among the live-token protocols in the same snapshot with at least
$50M of TVL, the median market-cap-to-TVL ratio is the multiple the board uses. On the shipped snapshot that sample
is 52 protocols and the median is **0.082×** — the market's own verdict on what a dollar of protocol TVL is worth in
token terms, read on the very same day the board is built. The dashboard publishes the sample, the median, and the
25th and 75th percentiles next to the number it used, because the spread (`0.032×` to `0.317×`) is wide enough that a
ranking which hides it would be misleading.

Coverage: the whole watchlist, plus every pre-token protocol under the $50M TVL floor taken by TVL, earliest first —
226 rows on the shipped snapshot from a 758-protocol universe.

The board says *records no token*, never *has no token*. The snapshot's silence is the evidence, and it is the only
evidence the board claims.

## The dashboard

Three files, no framework, no build step:

- `index.html` — the shell.
- `app.css` — a dark terminal theme; one palette, one type scale, a 4px spacing system.
- `app.js` — renders the board, the filters, the sort, the detail sheet and the methodology panel from `window.RADAR`.

Clicking any row opens its detail sheet: the factor waterfall that produced its value (so a reader can see exactly
which adjustment put one protocol above another), the full arithmetic spelled out, and a farm plan derived from the
row's own category, chains, TVL and age. Filters cover tier (all / watchlist / early), category and chain; every column
sorts.

## Run it

```bash
node main.ts --input input/snapshot.json --output out
```

`main.ts` reads the snapshot, writes `out/board.json` (every row in full, farm steps included), `out/data.js`
(`window.RADAR`, what the dashboard renders), copies `dashboard/` and `screenshots/` into `out/`, and writes
`out/dossier.json` last. Standard library only, no dependencies.

To look at the dashboard, serve the output directory so `../data.js` resolves:

```bash
python3 -m http.server -d out 8000   # then open http://localhost:8000/dashboard/
```

## Layout

```
main.ts              entry point: snapshot in, /output out
lib/model.ts         the model: filters, calibration, scoring, farm plans, the dossier
dashboard/           index.html, app.css, app.js — the board as the judge reads it
screenshots/         1-board.png, 2-detail.png, 3-filtered.png
out/                 what the entry hands in, regenerated by every run
```
